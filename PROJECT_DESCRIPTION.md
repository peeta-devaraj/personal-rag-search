# Personal RAG Search

**A fully local, hybrid-retrieval Q&A system over your own documents — built to demonstrate real
Information Retrieval engineering, not just an LLM API wrapper.**

## The problem

Most "RAG demo" projects are a thin script: chunk some text, embed it, cosine-similarity search, stuff
into a prompt. That's enough to answer a question, but it skips over almost everything that actually
matters in information retrieval — and it gives no way to know whether the retrieval is any good.

This project instead asks: *if I actually apply IR fundamentals (sparse + dense retrieval, rank fusion,
re-ranking) and build a real evaluation harness, how much does it actually help — measured on my own
documents, not a public benchmark?*

## What it does

Upload your notes, lecture PDFs, or papers. Ask a question in plain English. Get an answer generated by a
local LLM, grounded in and cited back to the exact passages it came from — with zero cloud API calls,
zero cost, and full privacy (everything runs on-device via Ollama).

## What makes it substantial, not a toy

- **Hybrid retrieval, not just cosine similarity.** Dense retrieval (`BAAI/bge-small-en-v1.5` embeddings +
  ChromaDB) and sparse retrieval (BM25 via `rank_bm25`) run independently and are combined with
  **Reciprocal Rank Fusion** — because a BM25 score and a cosine similarity live on incomparable scales,
  and naively averaging them would be wrong.
- **Cross-encoder re-ranking.** The fused candidate set gets a second pass from
  `cross-encoder/ms-marco-MiniLM-L-6-v2`, which jointly encodes (query, passage) pairs — more accurate
  than the bi-encoder similarity used for the initial retrieval, but too slow to run over an entire
  corpus, so it only touches the ~20 fused candidates.
- **A real evaluation harness, not a vibe check.** Since a personal document library has no query log to
  evaluate against, the app auto-generates a synthetic gold set — one question per chunk, written by the
  local LLM — and reports **Precision@k, Recall@k, MRR, and nDCG@k** comparing BM25-only vs dense-only vs
  hybrid+rerank, on the actual corpus you loaded. It also documents the honest limitation of that approach
  (synthetic questions echo their source passage's wording, which can flatter BM25) instead of hiding it.
- **A measured, real result.** After loading a 1,600-chunk machine learning textbook alongside a handful
  of short notes, a 107-query eval run showed BM25 actually *winning* on MRR (0.842) against dense
  (0.713) and hybrid (0.822) — a genuinely interesting finding that matches known IR literature (lexical
  matching is hard to beat when queries share exact terminology with the source), not a result staged to
  make hybrid look best.
- **A full-stack app, not a notebook.** FastAPI backend with a proper ingestion pipeline, SQLite metadata
  store, and background-task handling for slow LLM calls; a React + TypeScript frontend with a Library,
  a chat-style Ask view with live retrieval-strategy switching, and an Eval Dashboard with a metrics
  comparison chart.

## Engineering details worth knowing about

- **Sentence-aware chunking with overlap**, not naive fixed-size windows — chunks target ~300 tokens with
  ~50 tokens of carried-over context, so chunk boundaries don't cut mid-thought.
- **Async-safe ingestion.** Large-file embedding is CPU-bound work; running it directly on FastAPI's
  event loop would freeze the entire server for every other request (a bug this project hit and fixed —
  ingestion now runs in a thread pool).
- **BGE's asymmetric retrieval convention** is handled explicitly: queries get an instruction prefix,
  documents don't — a detail that's easy to get silently wrong and quietly tanks retrieval quality.
- **Every document/chunk/eval-run is persisted** (SQLite + a persistent Chroma collection + a BM25
  pickle), so the app survives restarts and eval runs are comparable over time as you tune parameters.

## Tech stack

**Backend:** Python, FastAPI, SQLAlchemy/SQLite, PyMuPDF, `sentence-transformers`, ChromaDB, `rank_bm25`,
Ollama (local LLM inference).

**Frontend:** React, TypeScript, Vite, Tailwind CSS, Framer Motion, Recharts, Lucide icons.

## Result you can reproduce

The repo ships with a small bundled sample corpus (original short notes on BM25, PageRank, transformers,
embeddings, evaluation metrics, inverted indexes, and query expansion) so the whole pipeline — ingest,
ask, evaluate — is demoable in a few minutes on a fresh clone, no dataset hunting required.
